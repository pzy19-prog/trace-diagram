# 路线 JSON v1

坐标以 prepare 产出的 sheet.png 的左上角为原点，水平 x 递增，垂直 y 递增。size 是 [宽, 高]。节点框为 [左, 上, 右, 下]，边的 points 从出发节点边界指向到达节点边界，逐段贴着原线。坐标的最大值为对应边长减 1。节点和边遵循 N1、E1 形式，编号稳定，可不连续。每条边有唯一编号；同一源和终点允许存在不同条件的平行边。condition 和 uncertain 是可选字符串。若 uncertain 非空，review 可供纠正，render 会拦截用到该边的场景。场景的 start 为已知节点，edges 非空、按播放顺序排列，可重复；疑似端点未知时给边填 null 并保留具体疑点。若完全无法判断路由，输出识别总览时省略 --scene，可令 scenes 为空。

```json
{
  "version": 1,
  "size": [500, 240],
  "nodes": [
    {"id":"N1","label":"检查材料","box":[40,60,160,120]},
    {"id":"N2","label":"退回补充","box":[300,60,420,120]}
  ],
  "edges": [
    {"id":"E1","from":"N1","to":"N2","condition":"材料缺失","points":[[160,90],[300,90]]}
  ],
  "scenes": [
    {"id":"return","label":"材料缺失","start":"N1","edges":["E1"]}
  ]
}
```

先在输入图像旁保留确定的原图文件，再为每个场景选不同输出文件名。CLI 使用现成路线执行渲染；从图片写出这份 JSON 的步骤在支持图像输入的 Agent 内运行。
